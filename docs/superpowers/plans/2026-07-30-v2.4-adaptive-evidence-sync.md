> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** adaptive 실행이 자기 evidence를 자기가 거부하는 2.3.0 회귀를 근본 수정(완료 판정 로직 단일화 + 검증 실패 evidence 보존)하고, 재발을 프로세스 레벨에서 막는 AGENTS.md 동기화 매트릭스를 신설한다.

**Architecture:** 완료 판정을 `core`의 순수 함수 `milestoneCompletionRule`로 단일화해 runtime(`advanceAdaptiveMilestone`)과 검증기(`validateAdaptiveExecutionEvidence`)가 같은 규칙을 공유한다. 검증 실패 시 run 디렉터리를 삭제하는 대신 `.invalid`로 rename해 보존하고, 모든 CLI 경로 해석기(`resolvePrivateQaPath`)가 `.invalid`를 거부한다. 문서는 3층으로 재편: CLAUDE.md(얇게, 릴리즈) → AGENTS.md(canonical, 아키텍처+매트릭스) → docs/(사용자·운영).

**Tech Stack:** Node 20+ ESM(.mjs), vitest, Playwright(chromium, 테스트 하네스), Changesets/pnpm monorepo.

## 사전 조사에서 확정한 실제 회귀 지점 (플랜의 근거)

1. **"out of sequence" 원인:** `packages/provider-playwright/index.mjs:167`이 시작 URL로 자동 goto한 뒤 `:170`에서 `currentPage`를 `{ ...initialInput.currentPage, url: gatewayUrl(page, …) }`로 재구성한다 — pageId·domGeneration은 보존되지만 **url이 redirect/정규화로 달라질 수 있다**. 검증기 `packages/cli/qa-native-adaptive-evidence.mjs:42-45`는 첫 audit의 `before`를 `input.currentPage`와 url까지 3필드 완전 일치(`sameAuditPage`)로 요구 → 실측 "milestone ID 일치, samePage=false"와 정확히 부합.
2. **"lacks accepted evidence" 원인 (유력 가설, Task 3에서 확증):** provider는 audit에 `satisfiedMilestoneIds: observation?.contract.satisfiedMilestoneIds ?? []`(`provider-playwright/index.mjs:278`) — 즉 **빈 배열**을 봉인한다. 검증기 `provesMilestone`(`qa-native-adaptive-evidence.mjs:78`)은 `satisfiedMilestoneIds === undefined`면 통과시키지만 **정의된 빈 배열이면 `includes(milestone.id)` 실패로 거부**한다. runtime(`core/index.mjs:268-278`)은 observe-only milestone(semantic 시나리오의 evidence-milestone, `target`/`expectation` 없음)과 boundElement 기반 `wait_for_element_state`를 satisfiedMilestoneIds 없이도 완료 처리 → runtime COMPLETED ↔ validator 거부 불일치.
3. **evidence 파기:** `packages/cli/qa-native-execute.mjs:101` `if (created) rmSync(runDirectory, …)` — 검증 실패 포함 모든 에러에서 run 디렉터리 삭제. 게다가 evidence archive 기록(`:71`)이 검증(`:53`)보다 **뒤에** 있어 검증 실패 시 디스크에 남는 것이 아예 없다. 보존하려면 실패 경로에서 archive를 써준 뒤 rename해야 한다.

```js
// Failed adaptive evidence is the debugging record of the failure itself: seal whatever the
// runtime produced, then quarantine the run as <dir>.invalid instead of deleting it.
function preserveInvalidRun({
  runDirectory,
  cwd,
  execution,
  agentInputs,
  writeArchive,
  integrityKey,
}) {
  try {
    writeArchive({
      directory: join(runDirectory, "evidence"),
      bundles: execution.bundles,
      manifest: execution.manifest,
      readBlob: execution.readBlob,
      integrityKey,
    });
    if (agentInputs !== undefined)
      writePrivateJsonExclusive(
        relative(cwd, join(runDirectory, "execution-agent-inputs.json")),
        agentInputs,
        { cwd },
      );
  } catch (sealError) {
    process.stderr.write(
      `qa-native: failed to seal invalid evidence — ${sealError.message}\n`,
    );
  }
  let preservedAt = runDirectory;
  try {
    renameSync(runDirectory, `${runDirectory}.invalid`);
    preservedAt = `${runDirectory}.invalid`;
  } catch (renameError) {
    process.stderr.write(
      `qa-native: failed to quarantine run directory — ${renameError.message}\n`,
    );
  }
  process.stderr.write(
    `qa-native: invalid adaptive evidence preserved at ${relative(cwd, preservedAt)}\n`,
  );
}
```

```js
// Single source of truth for "can this accepted action prove this milestone complete".
// The runtime (advanceAdaptiveMilestone) applies this rule PLUS live-only bindings
// (element handles, observation page match); the evidence validator applies exactly this
// rule — so validator acceptance is a necessary condition of runtime acceptance, never stricter.
export function milestoneCompletionRule(
  { action, parameters, satisfiedMilestoneIds } = {},
  milestone,
) {
  if (milestone.class === "REQUIRED_EXACT_ACTION")
    return action === milestone.requiredAction;
  if (milestone.class !== "REQUIRED_SEMANTIC_MILESTONE") return false;
  const observeAction = ["observe_dom", "observe_aria"].includes(action);
  const waitAction =
    action === "wait_for_element_state" &&
    ["present", "visible"].includes(parameters?.state);
  if (!observeAction && !waitAction) return false;
  if (milestone.expectation === undefined) return true;
  return waitAction || satisfiedMilestoneIds?.includes(milestone.id) === true;
}
```

```js
      : sameAuditPage(audit.before, expectedPage);
  if (
    milestone === undefined ||
    audit.proposal.milestoneId !== milestone.id ||
    !samePage
  )
    throw new Error("adaptive action evidence is out of sequence");
  expectedPage = audit.after;
  if (
    milestoneCompletionRule(
      {
        action: audit.proposal.action,
        parameters: audit.proposal.parameters,
        satisfiedMilestoneIds: audit.satisfiedMilestoneIds,
      },
      milestone,
    )
  ) {
    milestoneIndex += 1;
    while (
      milestone.class === "REQUIRED_SEMANTIC_MILESTONE" &&
      requiredMilestones[milestoneIndex]?.class ===
        "REQUIRED_SEMANTIC_MILESTONE" &&
      audit.satisfiedMilestoneIds?.includes(
        requiredMilestones[milestoneIndex].id,
      )
    )
      milestoneIndex += 1;
  }
});
```

로컬 함수 `provesMilestone` 삭제. `satisfiedMilestoneIds`의 while 배치 루프는 Task 3 사전 분석 결과 core `:283-289`와 의미가 갈리면 core 쪽 규칙으로 통일.
